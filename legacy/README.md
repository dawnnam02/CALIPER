# legacy — 이전 프로젝트 (CALIPER)

> **상태: 폐기 (2026-09-01)**
> 지우지 않고 남긴다. 왜 접었는지가 다음 판단의 근거이기 때문이다.

## 무엇이었나

**CALIPER** — 설계 캠페인이 자기 데이터를 거꾸로 읽고 있는지 검사하는 도구.

상위 N개만 실험하면 그 N개의 점수가 좁은 띠에 몰린다. 그 안에서 우연히
관계가 뒤집히면 "점수 높을수록 안 붙는다"는 환산표가 만들어지고,
그 표로 나머지 수만 개를 판단하면 **최악을 최고라고 부르게 된다.**
실측 사례에서 그 표는 남은 410개의 결합률을 96.2%로 예측했고 실제는 4.6%였다.

기울기 부호만 보면 잡아낼 수 있고, 웰을 하나도 더 쓰지 않는다.

## 남은 실측 근거

| | |
|---|---|
| 검증 캠페인 | 6종 (설계 55만 개, 표적 단백질 15종) |
| 단위 | 22개 (캠페인 × 표적) |
| 민감도 | 0.833 [0.552, 0.953] |
| 정밀도 | 1.000 [0.722, 1.000] |
| 발화했을 때 / 침묵했을 때 평균 ECE | 0.600 / 0.084 |

## 왜 접었나

**결과가 틀려서가 아니라 용도가 너무 좁아서다.**

- 이득이 **방어적**이다. 표가 멀쩡할 때는 아무것도 해주지 않는다
  (표를 믿고 고르나 무시하고 고르나 적중률 19.9%로 동일했다)
- **환산표를 애초에 만들지 않는 팀에게는 쓸모가 없다.** 상위 96개만
  실험하고 끝내는 곳이 이 분야에 적지 않다
- 경보를 울려도 **대안을 주지 못한다.** "이 표 쓰지 마라"까지가 전부다

## 되살릴 조건

- 결합체 설계에서 교정 곡선을 쓰는 것이 일반적인 관행이 되면
- 또는 이걸 파이프라인의 6단계 뒤에 붙여 **2라운드 설계에 쓰는 경로**가
  구체화되면 (지금 저장소의 `validation/check_filters.py` 가 그 자리에 있다)
